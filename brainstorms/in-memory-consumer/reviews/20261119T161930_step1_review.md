### Step-3. No test guards the cleanup in `waitForAppendOrAbort`

Quote: Diff: `const wake = () => { waitingReaders.delete(wake); signal.removeEventListener('abort', wake); resolve(); };`. Spec: a reader "waits until `append(...)` adds messages or the read's signal aborts; after each burst it yields the new messages and another `MessageSourceCaughtUp`."
Consequence: deleting `signal.removeEventListener('abort', wake);` or `waitingReaders.delete(wake);` keeps all 14 tests green. Without the first, each wait adds an abort listener to the consumer's signal (Node warns with `MaxListenersExceededWarning` after 10). Without the second, `waitingReaders` grows with dead callbacks on every burst. A possible test: run more than 10 bursts on one reader and check `getEventListeners(signal, 'abort')` from `node:events` is 1 while waiting and 0 after waking.
Belongs to: implementation
Resolution: fixed (Oskar: "Could you add such test?"). Added `keeps the same abort listeners on a reader across many bursts` to `inMemoryMessageSource.unit.spec.ts`: 20 bursts on one reader, the abort listener count while waiting stays the same. Without `removeEventListener` it fails (21 listeners instead of 1). The `waitingReaders.delete(wake)` cleanup is not observable through the source's API, so no test guards it.
