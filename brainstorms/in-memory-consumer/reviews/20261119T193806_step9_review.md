Quote: Step 8, `src/packages/emmett-sqlite/src/storage/sqlite3/eventStore/consumers/sqliteEventStoreConsumer.inMemory.projections.int.spec.ts`:

```ts
          globalPosition: metadata.globalPosition,
          checkpoint: metadata.checkpoint,
```

Step 9, in both `postgreSQLEventStoreConsumer.inMemory.projections.int.spec.ts` and `postgreSQLEventStoreConsumer.schema.int.spec.ts`:

```ts
            isAfterHandled:
              metadata.globalPosition > handled.metadata.globalPosition,

```

The Step 8 re-review (`reviews/20261119T192846_step8_review.md`) set the field list for this scenario: "map ... to `type, kind, schemaVersion, data, streamName, streamPosition, globalPosition, checkpoint, correlationId, causationId` ... This is the same field set as `assertWelcomed`." Step 9 drops `checkpoint` from both specs and keeps the other fields.
Consequence: this breaks the "assert every event field" convention and the Step 8 precedent that the step points to. If the appended event's `checkpoint` were wrong, both tests would still pass. PostgreSQL's `readStream.ts` sets `checkpoint: globalPosition`, so the fix is one line, for example `isCheckpointAtPosition: metadata.checkpoint === metadata.globalPosition`, or comparing `checkpoint` with the handled event's checkpoint the same way as `isAfterHandled`.
