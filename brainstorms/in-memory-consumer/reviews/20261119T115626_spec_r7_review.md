### Q&A-1. What in-memory processors get at runtime when no in-memory consumer supplies `session.messageStore`

Quote: Spec "`InMemoryProcessorHandlerContext` declares `session.messageStore: EventStore` as required, the same as SQLite's and PostgreSQL's processor contexts declare their message store (Q33)." / Q32 derived typing "optional, because an in-memory processor run outside a consumer has an empty session" / Q33 "Required, as in SQLite."
Consequence: SQLite can require it because each SQLite processor builds it in its own scope (`sqliteProcessor.ts:237-255`). In-memory processors only forward the host consumer's session (`inMemoryProcessors.ts:179-183`, `session: partialContext?.session ?? {}`, which stops compiling with a required field). In-memory processors already run on other consumers without a `messageStore`: MongoDB (`mongoDBEventStoreConsumer.handling.int.spec.ts:91`, scope passes `{ client }`), SQLite and PostgreSQL (`*.inMemory.projections.int.spec.ts`, scopes pass `{ pool, connectionOptions }`), EventStoreDB (`projectorFactory: inMemoryProjector`). There the type promises an `EventStore` and the handler gets `undefined`. EventStoreDB, whose processors also don't always have one, declares `messageStore?` optional (`eventStoreDBProcessor.ts:38`).
Belongs to: qa
Resolution: fixed in r8 (back to brainstorm: Q34 "A")
