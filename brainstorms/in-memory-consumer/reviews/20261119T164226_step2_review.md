### Step-7. Many copied handling and awaiter scenarios still check received events with partial, order-insensitive matches

Quote:

- `inMemoryEventStoreConsumer.handling.unit.spec.ts` uses `assertThatArray(...).containsOnlyElementsMatching(...)` at lines 106, 362, 477, 539, 543, 597, 598, 648, 737, 740, 820, 823, 878, 942, 1103, 1149, 1170, 1220, 1252 and 1310. Line 878 is the 2.5 scenario, "handles only new events when CURRENT position is stored for restarted consumer": `assertThatArray(result).containsOnlyElementsMatching(events);`.
- `inMemoryEventStoreConsumer.awaiters.unit.spec.ts` lines 56 and 98 (4.1/4.3): `assertThatArray(processed).containsElementsMatching(events);`.
- `containsOnlyElementsMatching` (`testing/assertions.ts:337`) checks the length and `other.every((ts) => array.some((o) => isSubset(o, ts)))`. `containsElementsMatching` does not check the length.
- Plan step 2, Tests: "Assert every field of received events." Spec, Testing Decisions: "Assert every field of received events, as the existing consumer tests do."

Consequence:

- These tests still pass on out-of-order delivery, or with a wrong or missing `metadata` value (checkpoint, globalPosition, streamPosition, messageId, `kind`, `schemaVersion`). This covers 2.5 and the END, CURRENT and restart scenarios.
- In the awaiter tests, a duplicated or extra delivery also passes, because `containsElementsMatching` has no length check. 4.1 says the reactor "saw all events", but a reactor that saw an event twice still passes.
- SQLite uses the same matchers, but the step and the spec ask for more, and the fixed copies already show the `assertDeepEqual(result, stored)` pattern.

Belongs to: implementation. The plan Tests header and spec Testing Decisions decide it.
Resolution: fixed (Oskar: "could you fix and align it"). All partial matchers in `inMemoryEventStoreConsumer.handling.unit.spec.ts` (20) and `.awaiters.unit.spec.ts` (2) replaced with `assertDeepEqual(received, stored.slice(...))` against the stream read back, so order, length and every field are checked. Other drivers' consumer specs have the same pattern; surveyed, not changed.
