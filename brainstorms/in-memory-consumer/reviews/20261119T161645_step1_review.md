### Step-1. No test runs the code that wakes a waiting reader; 12.2 never has a waiting reader

Quote: Diff: `append: (...appended) => { messages.push(...appended); [...waitingReaders].forEach((wake) => wake()); }`. Step 12.2: "GIVEN a reader that caught up AND timers that never advance WHEN messages are appended THEN the reader gets them". Test: `await reader.take(2); source.append(messageAt('2')); assertDeepEqual(await reader.take(2), ...)`.
Consequence: after `take(2)` the generator is paused at the caught-up `yield`, so no reader is waiting when `append` runs. With the wake line deleted, all 14 tests still passed, so a caught-up consumer could hang and no test would fail.
Belongs to: implementation
Resolution: fixed. The reader helper got `waitForMessages()`, which starts `next()` and settles before `append`. The 12.2, END, bursts and two-readers tests use it. With the wake line deleted, those 4 tests now fail.

Quote: Step: "12.5 ... asserts both reads yield the full list independently." Diff: `await first.take(2); await second.take(2);` with results thrown away.
Consequence: a second reader that skips existing messages would still pass.

Resolution: fixed. Both readers now assert `messageAt('1')` and its caught-up signal before the later append.
