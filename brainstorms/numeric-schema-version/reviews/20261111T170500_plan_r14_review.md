### Spec-1. 19.7 "a second run changes nothing" does not say how the migration runs twice

Quote: plan step 12: "19.7: "a second run changes nothing" - asserts nothing changes."; "each row gets its numeric `metadata.schemaVersion`, or `1`. The old column value is never used". Spec 19.7: "GIVEN the automatic migration has run WHEN it runs again THEN nothing changes."
Consequence: if "runs again" means `createEventStoreSchema` a second time, Dumbo's migrations table skips the swap and the test passes without testing the SQL. If it means running the swap SQL again, it rewrites the column from metadata, so a row holding `3` with no metadata version goes back to `1`. Step 11 settles this for PostgreSQL; step 12 does not.
Belongs to: plan (state which run the test uses); spec if the SQL must be safe to run twice.
Resolution: from the user: "OK" (fixed in r15: second `createEventStoreSchema`, nothing applied, rows unchanged)

### Spec-2. 19.1 test asserts a layout the spec has no criterion for

Resolution: from the user: "OK, but what's worth if all migrations will need to run nevertheless?" (PRAGMA equality dropped from 19.1 in r15; the extra test is open)
