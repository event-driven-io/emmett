### Step-12.3. Digits-only text too large for SQLite INTEGER is undecided

Quote: `THEN CAST(${metadataSchemaVersion} AS INTEGER)`. Spec: "A digits-only value too large for an `INT`... fails the cast: a migration stops with an error" (Q109, Q125), which describes PostgreSQL. Plan: "text matching only digits cast to `INTEGER`".
Consequence: SQLite's `CAST` never fails. `'99999999999'` is stored as `99999999999`, and a value over 2^63 saturates silently to `9223372036854775807`. No spec, qa or test decides the SQLite result.
Belongs to: spec
Resolution: from the user: "Dude stop bs me and to fng work" (Q134), decided in Q129 (1): SQLite uses its own CAST with no range check

### Rebuild-order deviation (no finding)

No observable change on a successful run: the final table name and DDL are the same, since `messagesTableSQLFor` produces the table in both orders, and SQLite renames the `UNIQUE` autoindex with the table before the old table is dropped. A collision with a user table named `<messages>_text_schema_version` is possible but negligible. On failure the order does not matter: `createEventStoreSchema` runs the migrations inside `pool.withTransaction` (`eventStore/schema/index.ts:87`), so the rollback restores the original table in both orders (checked by the coordinator).
