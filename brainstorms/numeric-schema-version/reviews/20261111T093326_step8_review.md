### Step-1. The optional-version branch takes any number for the bare `number` type, and an unmatched version for unions of versions

Quote: diff, `messageSchemaVersion.ts`: `> = undefined extends MessageType['schemaVersion'] ? Args | [...Args, schemaVersion: MessageSchemaVersionOf<MessageType>]`. Step 8: "A message type declared without a version, or with version 1, accepts an optional last argument `1` ... Any other number there does not compile." Spec, Helpers: "It is required when the type declares a version other than `1`, and optional otherwise. For a type declared without a version or with version `1`, the optional argument is `1`." Spec, Message types: "so V2 data can never be stored as version `1` by mistake".
Consequence: a tsc probe shows these calls compile now and failed at HEAD ("Expected 2 arguments, but got 3"): `event<Event>('A', {}, 7)`, `command<Command>('C', {}, 7)`, `command<Command>('C', {}, { now }, 7)`, `message<Event>('Event', 'A', {}, 9)`. The bare `Event`, `Command` and `Message` types now take any number. With `V1 = Event<'A', D1>` and `V2 = Event<'A', D2, undefined, 2>`, `event<V1 | V2>('A', { productId: 'p' }, 2)` (V1 data stamped as version 2) and `event<V1 | V2>('A', { x: 1 }, 1)` (V2 data stamped as version 1) both compile, because the union's `schemaVersion` includes `undefined` and falls into the unversioned branch. The step and spec do not decide either case, and the union case goes against the spec's aim that the wrong version cannot be stored by mistake. No test covers either case.
Belongs to: plan (step 8 should say how the bare `number` type and unions that include version 1 behave; if the answer is "a union must not take an explicit version", it belongs to spec, Helpers)
Resolution: fixed. The optional argument is now the literal `1`, as spec.md, Helpers: "For a type declared without a version or with version `1`, the optional argument is `1`." `event<Event>(..., 7)` and `event<V1 | V2>(..., d1, 2)` are rejected again, with `@ts-expect-error` checks. `event<V1 | V2>(..., v2Data, 1)` and the union without a version are the accepted limit (spec "Out of scope", Q77/Q99, docs 22.1).
