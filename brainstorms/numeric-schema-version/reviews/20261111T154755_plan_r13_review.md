### Spec-1. SQLite rebuild description does not apply "whole number of 0 or more" to integer metadata

Quote: plan step 12: "`INSERT ... SELECT` with the version from `json_type`/`json_extract` (`integer` taken as it is, `text` matching only digits cast to `INTEGER`, else `1`)"; r13 test: "rows with metadata `-1`, `0` and `'02'` give `1`, `0` and `2`, per the read rule". Spec read rule: "A value stored as a number is numeric when it is a whole number of `0` or more, and is taken as it is: `-1` and `1.5` count as missing... The same rule applies in the migration `COALESCE`".
Consequence: an implementer following the migration text keeps `-1` as `-1`, and the test expecting `1` fails; they must guess which one is right.
Belongs to: plan
Resolution: from the user: "Ok" (fix the migration text to take an `integer` only when it is 0 or more, else `1`)
