### Step-2. The plan's "Append rule" term still describes the reversed Q116 rule

Quote: plan Terms: "**Append rule.** Every store persists the top-level `schemaVersion`, or `1` when it is missing. ... Code that still sets only `metadata.schemaVersion` gets `1` (Q7)." Spec r12: "When it is missing, the store takes `metadata.schemaVersion` if it is numeric by the read rule, else `1` (Q122)." Step 13 "What to build": "SQLite appends write the top-level `schemaVersion ?? 1` into the column".
Consequence: step 10's code follows spec r12 and Q122. The Terms and the step 13 text contradict them, so step 13 may build the reversed rule.
Belongs to: plan
Resolution: open. Spec r12 and Q122 decide the rule, and step 10 follows them. The plan text (Terms and step 13) needs an update by the plan owner. Step 10 does not need it.

### Standards-1. Several new tests check only some fields of the recorded messages they read

Quote: `events.map(({ metadata }) => metadata.streamPosition)` (12.3), `events.map(({ schemaVersion }) => schemaVersion)` (14.4, 15.3), `{ schemaVersion, metadataSchemaVersion }` and `current.events.map(...)` (24.1), `read.map(({ schemaVersion }) => schemaVersion)` (the metadata copy test). Consequence: these tests would not catch a wrong `kind`, `data` or metadata, or wrong positions.
Belongs to: implementation
Resolution: fixed. All five tests assert whole recorded events. 12.3 also mixes versions (`'2'`, `3`, none, none), and 24.1 and 15.3 assert the whole stored rows.

### Standards-2. The new describe repeats existing helpers and builds the released 0.43.0 store differently

The initial record stays in the local helper, because moving it into `releasedMigrations_0_43_0` would change the step 1, 7 and 9 tests, and this step does not ask for that. Steps 11 and 12 should decide whether to share it.
